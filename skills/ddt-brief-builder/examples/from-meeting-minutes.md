# 示例 D：会议纪要 + 功能清单 xlsx + 人员表 xlsx → brief（B2B 多模块实战）

> 来源：v0.9.2 实战项目"无人物流车运营服务平台 V1.0"
> 这是 examples/ 中**最复杂的实战场景**——涉及 B2B + 多模块 + 外部接口 + baseline 增量 + xlsx 自动 dump。

## 用户输入（实战）

```
请基于 design/比赛项目/ 目录下三份文件帮我写 brief：
- 无人物流车运营服务平台V1.0-产品设计交流-会议纪要.md
- 无人物流车运营服务平台V1.0-功能清单.xlsx
- 项目人员需求计划表.xlsx
```

## 输入识别（开场）

- **类型 G 多源混合**，明细：
  - **B 文件路径**（.md 会议纪要）
  - **H 会议纪要**（含 ※ 标识 / "客户代表" / "目标上线日"）
  - **I 功能清单 xlsx**（文件名含"功能清单"）
  - **J 人员/工时表**（文件名含"人员需求"）

LLM 开场说：
```
识别到 4 类输入混合（会议纪要 + 功能清单 + 人员表）。处理路径：
1. 会议纪要 → §1/§2/§3 主体（客户驱动模式，含 ※ P0 标识）
2. 功能清单 xlsx → §4 多模块归类（B2B 6 模块）
3. 人员表 xlsx → baseline 信息源（不塞 brief 字段，但提取团队规模/时间窗到 §5）

xlsx 不能直接 Read，将用 Bash + python3 openpyxl 自动 dump。
B2B + 多模块 + 客户驱动信号 → D1 决策门首选 java-modern（不是默认 node-modern）。
```

## xlsx 自动 dump

```bash
python3 -c "import openpyxl; print('OK')"  # 确认依赖

# 功能清单 dump
python3 -c "
import openpyxl
wb = openpyxl.load_workbook('design/比赛项目/无人物流车运营服务平台V1.0-功能清单.xlsx', data_only=True)
ws = wb['Sheet1']
for row in ws.iter_rows(values_only=True):
    cells = [str(c) if c is not None else '' for c in row]
    if any(c.strip() for c in cells):
        print(' | '.join(cells))
"

# 人员表 dump（同模式）
```

得到 6 模块 / 13 子功能 + 7 角色人员明细。

## 字段提取与填充

### §1 项目背景 ✅（来自会议纪要 + 功能清单 dump）

> 万集科技为物流客户开发**无人物流车运营服务平台 V1.0**——B2B 多客户管理后台。
> 痛点：**车辆异常时如何及时收到提醒**（管理中最棘手问题）+ 车辆/客户/网点/路线信息分散。
> 为什么现在做：客户运营效率瓶颈 + 车队规模扩大 + 安全合规审计要求 + 与车企接口集成时机成熟。

### §2 目标用户 ✅（甲方/乙方两类，B2B 特化）

- **甲方（万集运营人员）**：日常监测车辆 / 处置告警 / 维护客户合同 / 分析事故，每天高频使用
- **乙方（客户：物流公司，如高洁/贾总代表方）**：决策方（评审产品方向）+ 间接受益方（车队运营效率提升）

### §3 成功标准 ✅（来自会议纪要"目标上线日 + 核心目标"）

**v1.0 硬指标**：
- [ ] 2026-01-30 v1.0 上线（**会议纪要明示**，前端/UI 角色离场日对齐）
- [ ] 实时告警监测覆盖 100% 在管车辆（"先解决最棘手问题"）
- [ ] 告警处置流程闭环（异常停留 / 电量过低 两类，带原因分析 + 状态机）
- [ ] 5 大基础信息模块（客户/网点/车辆/路线/系统）增删改查可用
- [ ] **`<待用户确认>`：v1.0 上线后客户运营人员单次告警处置 ≤ N 分钟**（建议补具体数字）

### §4 核心功能 ✅（**模块化结构，按 6 模块归类，含 P0/P1 标识**）

```markdown
### 模块 1：运行监测（P0，会议纪要 ※）
- 数据可视化展示：地图实时位置 + 状态 + 告警动态
- 地图操作：缩放聚合（区域车辆与告警汇总）
- 实时告警：异常停留 + 电量过低（其余告警 v1.1+ 规划）
- 告警消息推送：飞书 + 短信
- 告警逻辑（自动监测 / 自动结束）：异常停留→车辆移动后已结束；电量过低→充电达阈值后已结束
- 告警处置：详情查看 + 异常停留原因分析（字典管理 by 管理员）
- 辅助：网点/停靠点地图同步 + 两侧统计概览（在线/任务/告警数）

### 模块 2：任务记录（P0，会议纪要 ※）
- 任务详情、轨迹回放、任务告警、告警分析、告警关联事故
- （v1.1）任务聚合按"次"展示 + 总耗时（依赖车企接口）

### 模块 3：事故管理（P0，会议纪要 ※）
- 事故信息增删改查
- 信息预填：从告警关联创建事故时自动带入告警时间/地点/车辆
- 字段：责任主体二级下拉（追尾/降速/变道，由管理员维护）+ 事故处理人

### 模块 4：基础信息管理（P0，会议纪要 ※）
- 客户管理：客户档案 + 合同有效期（含到期提醒）+ 账单日 + 付款周期 + 关联网点/车辆
- 网点管理：网点基础信息 + 运营时段
- 车辆管理：车辆资产数据库（多条件查询 + 增删改查 + 数据接入；车辆基础信息通过车企接口同步）
- 路线管理：多品牌车辆通用配送路线（地图可视化 + 站点详情）

### 模块 5：系统配置管理（P0）
- 用户管理：账户增删改 + 角色绑定
- 角色管理：菜单/按钮权限矩阵
- 机构管理：树形组织架构
- 字典管理：枚举值统一维护

### 模块 6：日志管理（P1）
- 操作日志：操作人/时间/模块/动作/对象/结果（多维查询）
- 登录日志：登录人/时间（多维查询）

### 后续版本（P1/P2，会议纪要明示"v1.1 后续规划"）
- P1：告警视频回放 / 实时车载视频画面（依赖车企接口能力）
- P1：电池健康度分析 + 充电监控可视化
- P2：高频事故路线深度分析报表 / 维修记录闭环
```

### §5 关键约束 ✅（**B2B 特化：截止日期 + 团队 + 外部接口 + reasonability**）

```markdown
### 时间约束
- **v1.0 上线日**：2026-01-30（会议纪要明示，**硬约束**）
- **总开发窗口**：2026-01-04 ~ 2026-03-15（约 2.5 个月，含 v1.1+ 迭代）

### 团队规模（来自人员需求表）
- **总人月**：5.0 人月 ≈ 880 工时
- **团队组成**：项目经理/架构 1.4 + 产品 0.8 + UI 0.3 + 前端 ×2 共 1.2 + 后端 0.8 + 测试 0.5
- **v1.0 攻坚期**：2026-01-12 ~ 2026-01-30（前端 1.14 进 / 1.30 离场，对齐 v1.0 截止）

### 外部接口依赖
- **车企接口（待技术对接）**：
  - 车辆基础信息同步（客户/路线/品牌）—— 影响 §基础信息管理
  - 实时车辆位置 / 状态 / 告警数据 —— 影响 §运行监测
  - 任务"段"数据接入 —— 影响 §任务记录（v1.1 聚合依赖）
  - 视频流（告警时刻片段 + 实时车载画面）—— 影响 §运行监测 + 任务记录（v1.1+）
- **飞书接口**：告警移动端推送（待确认 webhook 配置）
- **短信网关**：告警短信推送（待确认采购）

### 合规与安全
- 告警/事故/操作日志全程可追溯（管理员维护字典）
- 操作日志不可编辑/删除（审计要求推断）
- 多客户数据隔离（客户管理是车辆分配与权限隔离的基础）

### 工期 reasonability check
- 6 模块 × 平均 4 子功能 = 24 leaf 功能 + 5 个外部接口集成
- B2B 后台基准估算：6 × 8 + 24 × 4 = 144 工时（不含外部对接）
- 外部接口集成估算：5 × 16 = 80 工时（含联调）
- **合计 ~224 工时 vs 计划 880 工时（5.0 人月）**——团队规模充足，**reasonability ✅ 通过**
```
