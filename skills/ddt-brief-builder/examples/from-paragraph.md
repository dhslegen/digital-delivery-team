# 示例 A：用户粘贴一段散乱描述 → brief

## 用户输入（实战）

> 我们公司有 30 多个开发，最近合规审计要求所有员工权限变更要可追溯。
> 现在是用 Excel 记录，时常对不上。我想做个内部小后台让 HR 自助操作，
> 还要能让审计部门一键导出报告。最好下个月底前能用上。

## 输入识别

- 类型：A. 自然语言描述（约 100 字）
- 信号：含痛点（"对不上"）、用户角色（HR / 审计）、约束（"下个月底"）、合规驱动（"审计要求"）

LLM 开场说："识别到一段自然语言项目描述（含痛点 + 用户 + 约束），将直接提取字段。"

## 字段提取

### §1 项目背景 ✅
> 公司 30+ 开发的权限变更目前用 Excel 记录，频繁对不上账，且合规审计要求权限变更全程可追溯。
> 痛点：手工 Excel 易错且不可靠；HR 想自助而非求开发；审计部门需要一键导出。
> 为什么现在做：合规审计驱动 + Excel 维护成本上涨。

### §2 目标用户 ✅
- **主要用户**：HR / 内部运营（每周 2-5 次权限变更操作，关注效率与合规）
- **次要用户**：审计部门（季度性导出报告，关注完整性）

### §3 成功标准 ⚠️ 部分可量化
- [ ] HR 自助完成单次权限变更 ≤ 3 分钟（取代 Excel + 找开发链路）
- [ ] 100% 操作可追溯（审计要求硬约束）
- [ ] 审计部门一键导出 CSV（覆盖时间范围 + 操作人 + 前后值）
- [ ] **`<待用户确认>`：上线后 1 个月内 HR 接受率 ≥ 80%**（可量化但需用户确认值）

### §4 核心功能 ✅
1. 成员列表（按部门/角色筛选 + 搜索）
2. 权限变更（赋予/撤销，含二次确认）
3. 审计日志（按时间/操作人/操作类型筛选）
4. 一键导出 CSV / PDF
5. 权限审批流（可选，看用户是否要）

### §5 关键约束 ✅
- **截止日期**：2026-06-30（"下个月底"，假设当前 2026-05）
- **预算 / 工期**：v0.8 验证 0.5-1 人天；v1.0 上线 5-8 人天估算
- **合规 / 安全**：SOC2 审计追溯要求（推断）；操作日志不可编辑

### §6 技术栈预设（决策门 D1）
**用 AskUserQuestion 问用户**——但根据输入信号"内部后台 + 30 人公司 + Excel 替换"，**preview 推 java-modern 或 node-modern**：
- java-modern：如果用户公司有 Java 团队（安全合规友好）
- node-modern：如果用户希望快速迭代（30 人公司可能更适合 Next.js + Prisma）

### §7 前端类型（决策门 D2）
**默认推 spa**（信号："小后台"含 UI / "HR 自助"需要交互界面）

### §8 AI-native UI 通道（决策门 D3，仅 spa 时问）
**默认推 claude-design**（公司内部使用 / 零外部账号成本）

### §9 非目标 ✅
- 不做密码重置（OAuth/SSO 由上游接管）
- 不做跨租户（单公司）
- 不做实时多人编辑

### §10 参考资料 ✅
（保留用户原始描述作引用）

## 决策门交互（3 个 AskUserQuestion）

LLM 一次性发 3 个 AskUserQuestion，让用户在 1 屏内完成决策：

1. D1 技术栈预设 → 用户选 node-modern
2. D2 前端类型 → 用户选 spa
3. D3 AI 通道（仅 spa）→ 用户选 claude-design
